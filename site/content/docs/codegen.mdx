The vast majority of this library is procedurally generated from the official Stripe OpenAPI specification. This ensures 100% field accuracy, correct types, and up-to-date coverage with Stripe's rapid API evolution.

## The Generator CLI

The code generation logic resides in the `openapi` crate. It is a standalone Rust CLI tool used to fetch specifications, analyze dependencies, and generate the library code.

### Running the Generator

To update the library to the latest Stripe API version, run the generator from the `openapi` directory:

```bash
cd openapi
# Fetches the latest spec from GitHub and regenerates code
cargo run --release -- generate --update-spec latest
```

### CLI Arguments

Commands use the release pinned in `openapi/version.json`. A matching local spec cache avoids downloading it again; missing, malformed, or mismatched caches are refreshed automatically. Generation also synchronizes fixtures. Updating the pin is explicit:

| Command or option | Description |
|-------------------|-------------|
| `generate` | Regenerates and installs bindings using the pinned release. |
| `generate --update-spec <VERSION>` | Updates to `latest` or an exact release such as `v171`. The pin advances after both the spec and fixtures are available. |
| `generate --no-install` | Generates and formats staging output without installing it. `--dry-run` is an alias. |
| `generate --out <DIR>` | Selects the output directory; defaults to `out`. Custom directories must be empty or belong to an earlier generator run. |
| `generate --report-dir <DIR>` | Writes analysis reports alongside generation, including crate inference warnings. |
| `analyze` | Writes dependency, placement, and item reports to `out/analysis` without generating bindings. |
| `analyze --graphs all` | Includes graph projections for expandable and ID-only references. |
| `analyze --without-expandables` | Computes placement without expandable references as an analysis-only counterfactual. |
| `update-api-docs` | Refreshes the Stripe documentation URL mapping. |

Run `cargo run -- --help` or a subcommand's `--help` for its options.

## Architecture & Workflow

To manage the complexity of the Stripe API, the generator performs several optimization passes:

1. **Inference**: Parses schemas and operations, assigns their identities, and records dependency facts with their source and reference kind.
2. **Retention & Layout**: Retains reachable components, uses `gen_crates.toml` to seed crate placement, and promotes model definitions into `async-stripe-shared` when required by cross-crate dependencies. The validated layout is then frozen.
3. **Model Rewrites**: Applies overrides and the existing component-local deduplication rules.
4. **Rust-model Lowering**: Assigns identities to generated declarations, resolves their references, and computes type properties separately from their names and locations.
5. **Rendering & Installation**: Renders bindings into staging, formats them with nightly rustfmt, and installs them unless `--no-install` was requested.

`analyze` stops after model construction and writes reports. Its expandable counterfactual changes placement analysis without changing generated API representations. See [`openapi/README.md`](https://github.com/arlyon/async-stripe/blob/master/openapi/README.md) for the pipeline and report formats.

### Configuration (gen_crates.toml)

The mapping of Stripe resources to Rust crates is defined in `openapi/gen_crates.toml`. This file controls the modular structure of the library and ensures related resources are bundled together.

```toml
# Example from gen_crates.toml
[[crates]]
name = "billing"
packages = ["test_helpers", "billing_portal", "billing"]
paths = [
    "credit_note",
    "tax_id",
    "invoice",
    # ...
]
description = "This crate provides Rust bindings to the Stripe HTTP API..."
```

## Manual Extensions

Because generated code is overwritten on every update, we strictly separate manual logic from generated logic.

- **Generated Code**: Lives in `generated/*`. This code is **never edited manually**.
- **Extensions**: Hand-written logic lives in `_ext.rs` files inside the resource crates or `async-stripe-types`. This allows us to add convenience methods (like currency helpers or custom serialization logic) without conflicting with the autogenerated structs.
